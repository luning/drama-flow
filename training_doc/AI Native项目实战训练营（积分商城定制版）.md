# 《AI Native 项目实战训练营》
## 积分商城平台定制版

## 课程简介

本课程以**积分商城平台（PointsHub）**为核心载体，带领学员完整经历从产品设计、原型制作、架构搭建到两轮迭代开发、集成测试、代码审阅与重构的全流程。课程通过实战将 AI-Native 研发的核心方法论——Spec 驱动开发（SDD）、Agent 友好型架构、Skills 及 MCP 设计、CR 与重构——全部落实在真实项目步骤中，让学员"做中学、学中做"。

五条知识体系贯穿实战过程，每条线在项目的不同阶段分层触发，形成"引入→深化→掌握"的学习螺旋。

课程时长 **1.5 天**（Day 1 全天 + Day 2 上午），教学形式以项目实战为主，辅以理论讲解和主题研讨。

## 项目介绍：PointsHub 积分商城平台

### 业务背景

积分商城是企业用户运营的核心手段之一：用户通过消费、签到、完成任务等行为积累积分，并在商城内兑换商品或优惠券。平台包含 **Web 端**和**移动端**，后端提供统一 REST API。

### 两轮迭代功能范围

**迭代 1 — 用户认证 + 商城首页 + 商品详情（Day 1）**

| 模块 | 必做功能 | 可选进阶 |
|------|---------|---------|
| 数据层 | User / Product / Category / PointsAccount 模型 + 测试种子数据（Day 1 上午）| 分页加载 |
| Auth | JWT 注册 / 登录 / 登出 + Token 刷新（Day 1 下午）| 企业 SSO 对接 |
| 首页 | 商品分类 Tab + 商品卡片列表（含积分价格）（Day 1 下午）| 骨架屏 + 搜索栏 |
| 商品详情 | 商品图片 / 描述 / 库存 / 积分价格 + 立即兑换按钮（Day 1 下午）| 用户评价区 |
| 移动端 | Android 登录页 + WebView 加载首页 | |

**迭代 2 — 积分核心业务（Day 2 上午前段）**

| 模块 | 必做功能 | 可选进阶 |
|------|---------|---------|
| 积分中心 | 积分余额展示 + 积分明细列表（收入 / 支出流水）| 积分到期提醒 |
| 积分兑换 | 积分扣减 + 库存锁定 + 订单创建（事务保证原子性）| 订单状态机（待发货→已完成）|
| 移动端 | 积分余额卡片 + 点击跳转 Web 兑换页 | 推送通知（积分变动）|

### Day 1

#### 1. 认知重构与 AI 编程经验（约1h）

> 目标：建立"AI Native"思维，以工程师实战经验为核心

**1.1 AI 能力演进的工程含义（15min）**

- 从补全到推理（CoT / o1 / o3）：能力跃迁对软件工程意味着什么
- S-P-A 架构速览：Agent 如何感知-规划-执行（规格驱动 / Agent 友好架构的理论基础）
- 三级记忆模型：为什么上下文管理是 Agent 的核心挑战
- 未来工作模式：全能个体 + 多 Agent 与 Harness + 上下文窗口与成本管理

**1.2 AI 编程核心经验（30min）**

十个关键认知，经验总结，配以演示：

1. 设计先行，架构不能外包
2. 用 CLAUDE.md 固化约束，而不是每次在 Prompt 里重复
3. 把需求写成结构化 Prompt，而不是口头描述
4. 小步拆解，每步可验证
5. 用好 Git，随时掌握节奏
6. 必须看代码，微观工程决策需要人来定，代码量增长后及时重构
7. 管理好 Session 和上下文窗口
8. 了解哪些任务 AI 不擅长
9. 分清执行类和架构类任务，善用对比提问
10. 对 Agent 保持高可观测性，保持人类最终裁决权（HITL）

**1.3 工具链说明（10min）**

- 工具与模型选择
- Claude Code 实用技巧

#### 2. 产品设计（55min）

> 目标：完成产品定义和可执行 Spec，掌握原型生成工具

**2.1 [实践步骤] PRD 生成（10min）**

- 任务：基于已知积分商城业务背景，直接生成 PointsHub PRD（跳过竞品分析）
- 产出：`PRD.md`（All-in-One 单文件）
  1. **产品定位与目标用户**：一句话定位、用户画像分层
  2. **功能范围**：按迭代划分，标注 P0/P1/P2 优先级，关联实现端
  3. **非功能需求**：积分事务一致性、库存并发、安全约束
  4. **技术架构概要**：React Web + Android + FastAPI + MySQL

**2.2 [实践步骤] 撰写可执行 Spec（20min）**

- **为什么 PRD 不够用**：PRD 描述"做什么"，Spec 描述"怎么做才算完成"，AC 可供 AI Agent 逐条自检
- **五段式格式**：领域名词 → 前置条件 → 主流程 → 异常处理 → 验收标准（AC）
- 范围：覆盖迭代 1+2 核心模块（Auth / Product / PointsAccount / Order）
- 产出：`SPEC.md` 初版
- 提效演示：让 Claude 从 PRD 草稿自动提取五段式 Spec 骨架，人工确认 AC
- **HITL 检查点**：AC 的最终确认必须由人完成，尤其是积分扣减的边界条件

**2.3 [实践步骤] 原型生成（25min）**

- **v0.dev**（React 技术栈首选）：输入 PRD 片段，直接生成可用 React 组件原型
- **Claude Design**（[claude.ai/design](https://claude.ai/design)）：描述需求直接生成交互原型，支持导出 React 代码
- **Claude Code 生成 HTML 原型**：零工具学习成本，从 PRD 直接生成，可快速浏览器预览
- **引入已有 HTML 作为参考模板**：v0.dev 可直接导入，Agent 类工具放入参考目录自动取用；跨工具延续既有设计风格
- **原型 + Spec 模式**：原型负责"看得见的流程"，Spec 负责"看不见但必须正确的逻辑"
- 产出：`prototype/` 可交互原型

#### 3. 项目工程化 + 方法论准备（60min）

> 目标：搭建 Agent 友好型项目骨架，写入最小约束，完成数据建模

**3.1 [Agent 友好架构] CLAUDE.md 是 Agent 的"宪法"，Repo 即 Agent 的"操作系统"**

**3.2 [实践步骤] 项目初始化 + 架构骨架（20min）**

- 指令示例
- 产出：
  - `frontend/`：React + Vite + TypeScript + Zustand + React Router 骨架
  - `backend/`（二选一）：
    - **Python**：FastAPI + SQLAlchemy 2.0 + MySQL 骨架 + Alembic 迁移配置
    - **Java**：Spring Boot 3 + JPA + Hibernate + MySQL 骨架 + Flyway 迁移配置
  - 每个模块的 README 模板

**3.3 [实践步骤][规格驱动] 撰写 CLAUDE.md + Prompt SDD 初体验（20min）**

- 写入技术栈说明、架构约束（禁止跨模块直接调用）、命名规范、构建命令、测试命令
- 写入 SDD 最小约束：接受任务前必须阅读对应 Spec，生成代码后自检 AC，修改 API 后运行 pytest
- **演示**："无 Spec" vs "有 Spec" 的 AI 响应差异；CLAUDE.md 中 SDD 约束如何影响 Agent 行为

**3.4 [规格驱动] OpenSpec：从 Prompt SDD 到工具化 SDD（15min）**

- 问题暴露：项目复杂度上升后纯 Prompt 约束的局限（约束易遗漏、AC 无法自动化验证）
- OpenSpec 核心能力演示：Change Proposal → Spec → Task → 实现
- 与 Prompt SDD 的对比：什么样的团队 / 项目值得引入工具化 SDD
- 说明：两者并存，下午开发时学员可自选使用

**3.5 [实践步骤] 数据模型设计（15min）**

- 任务：User / Product / Category / PointsAccount 数据模型 + 表结构 + 迁移脚本 + 测试种子数据（Python: SQLAlchemy + Alembic / Java: JPA + Flyway）
- **自我尝试**：第一轮不读 SPEC.md 直接让 AI 生成模型 → 第二轮加入约束重新生成 → 对比差异，体会 SDD 如何约束输出质量
- 重点关注：积分账户模型的并发安全设计（乐观锁字段）

*午休*

#### 4. 迭代 1：用户认证 + 商城首页 + 商品详情（约 2h50min）

> 功能：JWT 认证 + 商城首页（分类 + 商品列表）+ 商品详情页；数据模型已在上午完成

**4.1 [实践步骤] Auth 模块开发（35min）**

- 任务：认证接口（注册 / 登录 / JWT / Token 刷新）+ React 登录 / 注册页；Android 原生登录页
- **演示重点**：Claude Code 读取 CLAUDE.md + auth/README.md + SPEC.md → 生成代码（Agent 如何利用上下文）
- 开发策略：数据模型已就绪，直接生成 Auth Service + API 路由（后端），再生成 React 表单组件（前端）

**4.2 [实践步骤] 商城首页开发（45min）**

- 任务：`/api/products` + `/api/categories` 接口 + React 首页（商品分类 Tab + 商品卡片列表）
- Android：WebView 容器加载首页

**4.3 [实践步骤] 商品详情页（20min）**

- 任务：`/api/products/{id}` + React 详情页（图片 / 描述 / 库存 / 积分价格 / 兑换按钮）
- 根据 AC 补充 API 测试

**4.4 [实践步骤] 实现第一个 Skill（30min）**

- **Skill 设计理念与适用场景**：什么场景封装成 Skill？颗粒度如何把握？Skill 目录结构，参数设计原则
- **最佳实践**：幂等性（可重复调用不产生副作用）、结构化反馈（成功/失败/变更明细）
- **实现 `preview-deploy` Skill**：启动后端服务 + Vite Dev Server，供 PM 在浏览器中实时验收
- **实现 `db-reset` Skill**：重置 MySQL 测试数据（幂等，可重复调用，不重复插入）
- 讨论：Skill 内部的多步逻辑，应封装为脚本还是列步骤依赖 AI 推理执行

**4.5 [测试自愈] 怎么做测试（20min）**

- 选择 API 级测试：单元测试绑定实现，AI 加速后技术债积累更快，维护成本高于价值。后端测 API 行为，不测实现（Python: pytest / Java: Spring Test）
- 选择行为级测试：React 用 Cypress 测端到端用户操作流程，可以设计为利用 Claude Code 等 Agent 调度测试流程
- 用 AI 生成测试场景矩阵（正常 / 异常 / 边界），人工筛选关键场景
- **实现 `spec-validate` Skill**：以 Spec 为唯一来源，AC 覆盖检查，补充 API 测试，作为 SDD 的验收门
- 测试隔离注意点：每个测试用例前后的数据清理策略

**4.6 [实践步骤] CR + 重构（20min）**

- **实现 `cr-refactor` Skill**：输出 CR 清单 + 重构建议，参数最小化（只接受路径，自动定位问题）
- 寻找重构线索的提问框架及 AI 高频错误模式（重复逻辑 / 状态泄漏 / 命名混乱 / 不遵循设计 / 啰嗦的注释或实现）
- 学员按优先级执行 2–3 条重构，人工确认不破坏已通过的集成测试

### Day 2 上午

#### 6. 迭代 2：积分核心业务（约 2h30min）

> 功能：积分余额 + 明细 + 积分兑换下单；商品详情已在 Day 1 完成

**6.1 [实践步骤] 积分中心开发（35min）**

- 任务：`/api/points/balance` + `/api/points/history` 接口 + React 积分余额卡片 + 明细列表（收入 / 支出流水）
- Android：积分余额卡片 + 点击跳转 Web 兑换页（JSBridge）
- 根据 AC 补充 API 测试

**6.2 [实践步骤] 积分兑换下单（50min）**

- 任务：兑换接口（积分扣减 + 库存锁定 + 订单创建，事务保证原子性）+ React 兑换确认弹框 + 结果页
- **演示重点**：让 AI 生成带事务的 Service 层代码；识别 AI 容易遗漏的并发边界条件（积分不足 / 库存为 0）
- **HITL 检查点**：积分扣减、库存锁定的事务逻辑必须人工逐行审阅，不能依赖 AI 判断
- Bug 注入演练：故意引入竞态条件，让 Agent 读取日志自动定位；如何写"不脆弱"的并发测试
- 根据 AC 补充 API 测试

**6.3 [实践步骤] 迭代 2 CR + 重构（20min）**

- 两轮代码积累后的系统性重构：跨模块重复模式识别；重构 vs 重写的判断标准；保持行为不变的重构提示词
- Architecture as Code：演示将架构规则嵌入 pylint / ESLint 自定义规则，阻止 AI 生成违规代码；ADR 写法示例

**6.4 [实践步骤] Agent 自动化验收 / 探索性测试（15min）**

- 设计验收场景：从登录到积分兑换的核心路径，明确预期屏幕和通过条件
- 理解 Skill 如何编排"截图→观察→定位→操作→记录→检查"的执行循环
- 运行测试，修复遇到的步骤不合理等问题

**6.5 [实践步骤] 实现 MCP Server（30min）**

- 场景：运营人员通过 AI 查询用户积分余额和兑换订单，不能暴露原始数据库权限
- 任务：为 PointsHub 实现一个只读 MCP Server，暴露两个工具——`get_user_points`（查积分余额）和 `get_order_history`（查兑换记录）
- **演示重点**：MCP 工具定义 → 在 Claude Desktop / Claude Code 中注册 → 用自然语言触发工具调用
- **与 Skill 对比**：Skill 编排 Agent 的执行流程，MCP 向 Agent 暴露受控的系统能力——两者解决不同层次的问题

- 效率提升的正确度量：不是"代码生成速度"，而是"交付质量 × 速度"

**7.2 Skills 与 MCP 设计（25min）**

- 本课程中多个 Skills 的设计复盘：哪里设计好了，哪里还可以改进
- 企业级 Skill 库：分层（个人 / 项目 / 团队）、版本管理、共享机制
- MCP 三大能力的分工：Tools（可调用函数，AI 决定调用时机）/ Resources（只读上下文注入，给 Claude 补充背景）/ Prompts（固化高频诊断流程模板）
- Skill + MCP 可组合：两者不互斥——Skill 编排高层流程，MCP Tool 负责具体数据访问；复杂场景下组合使用比单独使用更强

**7.3 SDD 生态全景与选型指南（25min）**

- 回顾两层 SDD 递进：Prompt SDD（迭代 1）→ OpenSpec（迭代 2）
- SDD 生态一览：
  - **GSD**（上下文工程层）：新鲜上下文隔离 + 波级并行编排，解决长任务上下文衰减
  - **OpenSpec**（变更隔离层）：棕地优先，变更目录防串扰 + 完整审计追踪
  - **Spec Kit**（企业治理层）：规格即契约，宪法机制统一团队规范
- 构建团队自己的 SDD：基于已有框架裁剪或组合，形成团队开箱即用模板

**7.4 存量系统 Agent 友好改造（20min）**

1. **模块化 MD 优先**：从变动最频繁的模块开始，先写 README 再改代码
2. **DDD 划分限界上下文**：将 Agent 任务限制在局部，压缩单次推理负担
3. **接口契约标准化**：OpenAPI / Protobuf 描述所有接口，减少 Agent 通讯幻觉
4. **典型任务的实现路径**：通过提炼典型任务帮助模型快速理解如何在设计约束下实现复杂任务
5. **ADR 历史决策记录**：让 Agent 不重蹈覆辙；从 Git History 提炼实现模式

Architecture as Code 工具链：ruff / pylint（Python）/ ESLint（React）将架构规则嵌入 CI，由机器代替人工审查。
