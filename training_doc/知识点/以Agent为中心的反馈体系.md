> Agent 能自主推进，依赖的是可靠的反馈信号。这些信号来自两个层次，层次不同，优化的对象不同，但目标一致：**减少人作为中转站的必要性**。

## 对象层：应用给 Agent 的反馈

**信号方向**：应用系统 → Agent

**核心问题**：Agent 改了代码之后，它能不能自己知道对不对？

依赖两个条件：

- **可观测性**：系统能表达自身状态——结构化日志、有上下文的错误信息、状态机转换记录
- **可测试性**：行为能被可靠验证——清晰的测试接缝、稳定的自动化、明确的测试范围边界

两者缺一不可。可观测性差，Agent 读不懂现象；可测试性差，Agent 改完无法自证正确。

失效症状相同：人被迫成为信息中转站——粘贴日志、描述复现步骤、手动联调确认效果。

→ 详见《对象层反馈：可观测性与可测试性》

## 元层：Agent 行为给 Harness 的反馈

**信号方向**：Agent 行为记录 → Harness

**核心问题**：Harness 如何基于 Agent 实际运行的数据持续进化，而不是靠人的经验拍脑袋调整？

AHE（Agentic Harness Engineering）用三个可观测性支柱来驱动这个演化循环：

| 支柱 | 观测对象 | 作用 |
|------|---------|------|
| **组件可观测性** | Skill / Prompt / 工具定义以文件形式存在，git diff 即变更记录 | 让每次 Harness 修改都可追溯 |
| **经验可观测性** | session JSONL → 失败模式 → 跨任务基准 | 从海量轨迹中蒸馏出有效信号 |
| **决策可观测性** | 每次修改附带"预测效果"，下一轮验证是否兑现 | 让演化有方向，而不是随机试错 |

失效症状：Harness 靠感觉调、调了不知道好没好、好了不知道为什么好——演化退化为 trial-and-error。

→ 详见《Agentic Harness Engineering》

## 两层的关系

两层是独立的反馈循环，但互相影响：

- 对象层的信号质量，决定了元层能分析什么。如果应用测试抖动、日志模糊，session 记录里充满噪声，元层就很难从中提取真实的失败模式。
- 元层的 Harness 优化，改善了 Agent 在对象层的工作方式——更好的 Skill 让 Agent 更准确地使用测试工具，更好的上下文注入让 Agent 更快读懂日志。

**一个实用的优先级判断**：

如果 Agent 频繁需要人介入——先看是哪一层的问题：

```
Agent 读不懂报错 / 测试结果不可信  →  对象层问题，优先改应用
Agent 反复犯同一类错误 / Skill 失效  →  元层问题，优先分析 session 日志、优化 Harness
```

两层同时失效时，优先修对象层——没有可靠的信号，元层的分析也是沙上建塔。
