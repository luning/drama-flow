# 1.1 AI 能力演进的工程含义（20min）

---

### 从补全到推理：一次范式跃迁

```
2020  GPT-3        概率补全    "下一个词是什么？"
2022  ChatGPT      对话理解    "你说的意思是什么？"
2023  GPT-4        多步推理    "这个问题怎么解？"
2024  o1 / o3      思维链搜索  "先想清楚再回答"
2025  Claude 4     Agent行动   "我来帮你做完"
2026  Agent 爆火   规模化落地  "我们雇了多少个 Agent？"
```

**对软件工程意味着什么？**

| 旧模型能力 | 新模型能力 |
|-----------|-----------|
| 补全已知代码 | 设计新模块结构 |
| 解释单个函数 | 理解跨文件依赖 |
| 写简单测试 | 生成测试矩阵 + 边界分析 |
| 复现 StackOverflow 答案 | 给出多方案权衡 |

> **核心转变**：从"你帮我打字"到"你帮我思考"

### S-P-A 架构：Agent 的工作原理

```
┌──────────────────────────────────────────────────────┐
│                     Agent 执行循环                    │
│                                                      │
│   SENSE（感知）                                      │
│   ├── 读文件、读代码、读测试结果                       │
│   ├── 接收用户指令 / Spec 约束                        │
│   └── 获取工具反馈（Bash 输出、报错信息）              │
│                  ↓                                   │
│   PLAN（规划）                                       │
│   ├── 分解任务为子步骤                                │
│   ├── 识别依赖和风险                                  │
│   └── 选择执行路径                                    │
│                  ↓                                   │
│   ACT（执行）                                        │
│   ├── 调用工具（写文件、运行命令）                     │
│   ├── 观察结果 → 返回 SENSE                          │
│   └── 完成 or 报错 → 等待人工介入                     │
└──────────────────────────────────────────────────────┘
```

**为什么这解释了 SDD 和 Agent 友好架构？**

- Agent 在 SENSE 阶段读取的是：`CLAUDE.md` + `SPEC.md` + 模块 README
- 写得越清晰，PLAN 越准确，ACT 越少出错
- **结论**：文档质量 = Agent 执行质量

### 三级记忆模型：上下文管理为何如此关键

```
┌─────────────────────────────────────────────┐
│  Level 1：上下文窗口（In-Context Memory）     │
│  容量：128K–1M tokens                        │
│  特点：最快、最精准、用完即消失              │
│  对应：当前对话 + 打开的文件                 │
├─────────────────────────────────────────────┤
│  Level 2：外部存储（External Memory）        │
│  容量：无限                                 │
│  特点：需检索，有延迟，依赖索引质量          │
│  对应：CLAUDE.md / SPEC.md / 代码库          │
├─────────────────────────────────────────────┤
│  Level 3：参数记忆（Parametric Memory）      │
│  容量：固化在权重中                          │
│  特点：无需检索，但知识有截止日期            │
│  对应：模型训练数据（可能过时！）            │
└─────────────────────────────────────────────┘
```

**工程师需要管理的是 Level 1 和 Level 2**

- Level 1 耗尽 → 幻觉增加、前文约束失效
- Level 2 质量差 → Agent 找不到正确上下文

> **常见事故**：上下文超过 70% 后 Agent 开始"忘记"早期的架构约束

### 未来工作模式

**今天（2025）**

```
一个工程师  ←→  一个 AI Assistant
                  │
                  └── 单线程对话
```

**正在发生**

```
一个工程师  ──→  CLAUDE.md + SPEC.md + Skills
                  │
                  ├── Agent A：写后端
                  ├── Agent B：写前端  （并行执行）
                  └── Agent C：跑测试
```

**带来的挑战**

| 挑战 | 应对策略 |
|------|---------|
| 上下文碎片化 | 结构化文档代替口头约束 |
| 并行 Agent 冲突 | 模块边界清晰、接口先行 |
| Token 成本上升 | 精准上下文 > 塞入全量代码 |
| 质量失控 | HITL 节点 + 行为级测试兜底 |
