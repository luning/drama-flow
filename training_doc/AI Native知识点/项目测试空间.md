# 测试项目空间参考布局 - 设备软件测试 Agent 的工程基座

> **定位**：本文是《Harness 工程之项目空间》在测试领域的实例化——把"项目空间四层架构"落到半导体设备软件测试场景，给出一个可直接参照搭建的目录布局与逐区说明。配合培训大纲第六部分使用。

---

## 测试项目空间与开发项目空间的关系

开发项目空间围绕"改代码"组织（模块 README、ADR、Architecture as Code）；测试项目空间围绕"生成、评审、执行、诊断"四类任务组织，核心资产不是源码，而是**规格、领域知识、用例/Mission、经验与执行留痕**。

部署位置二选一：

| 方式 | 适用场景 | 代价 |
|------|---------|------|
| 独立仓库（推荐） | 测试团队自治、覆盖多产品线/多被测仓库 | 需维护"被测软件版本 ↔ 资产基线"的映射文件 |
| 挂在被测软件仓库内（如 `test-workspace/`） | 单产品线、测试与开发同仓协作 | 随被测软件分支走，多版本并行时资产易分叉 |

设备软件版本分支多、生命周期长，多数团队适合独立仓库 + 版本映射。

## 四层归类与约束强度

目录树中的要素按职责归入四层，**约束越往下越硬**（靠工具强制而非 Agent 自觉），成熟的空间四层联防：

| 层 | 对应目录 | 约束强度 | 强制方式 |
|---|---------|---------|---------|
| **文档层** | CLAUDE.md、spec/、knowledge/、templates/ | ★★☆☆☆ | Agent 自觉遵守，渐进披露按需加载 |
| **经验层** | experience/（INDEX 索引 + 分类经验文件） | ★★☆☆☆ | 任务关键词触发加载；高频场景封装进 Skill 强制 Read |
| **约束层** | .claude/hooks/、settings.json 权限 | ★★★★☆ | 运行时拦截：校验不过不得入库，危险操作必须人工确认 |
| **执行层** | .claude/agents/、skills/、commands/、scripts/、reports/ | ★★★★☆ | 工具白名单 + 确定性脚本 + 结构化留痕反馈回路 |

## 测试空间的"地基"

四层是外挂的工程制品，它们共同依赖一个地基：**测试资产本身的结构化程度**（对应开发空间的"代码库基础结构"）：

- **资产按"产品线 × 主题"colocate**：去胶的状态表、报警表、参数规格放在一起，Agent 处理去胶任务时不会误读 RTP 的参数——对应 DDD 的限界上下文
- **通用语言**：用例、知识文件、日志解析规则共享同一套设备领域词汇（与被测软件的术语一致），LLM 基于语义匹配推理，命名一致性直接决定定位准确率
- **形式化优于散文**：状态转换表、时序约束表、参数规格表是"强类型"的领域规格——对应接口契约标准化，表格化的规格比描述性文字更能防幻觉

地基差（资产是散落的 Word 和口头约定），四层建得再好也事倍功半。

## 治理与 Git 管理

**提交边界**——代表团队共识的提交，个人与机器自生成的忽略：

| 处理 | 内容 |
|------|------|
| 提交 | CLAUDE.md、spec/、knowledge/、experience/、templates/、missions/、scripts/、.claude/（agents/skills/commands/hooks/settings.json） |
| 不提交 | .claude/settings.local.json（个人权限偏好）、.claude/memory/（Agent 个人记忆）、reports/runs/（执行留痕，量大且机器生成——进制品库或定期归档，summary 可按需提交） |

**Review 分级**——判断标准：这个改动会让 Agent 在不知情的情况下做出不同决策吗？

| 级别 | 文件 | 要求 | 理由 |
|------|------|------|------|
| 严格 | CLAUDE.md、hooks/、agents/、skills/、settings.json | 必须 PR + 至少一人 Approve | 一条错误规则让 Agent 系统性产出问题用例，破坏力大于单点代码 Bug |
| 业务确认 | spec/baseline/ | AC 逐条人工确认（HITL）后才可基线化 | AC 是全空间溯源锚点与质量合同 |
| 正常 | knowledge/、experience/、templates/ | 建议 PR Review | 影响生成质量，但不直接改变 Agent 执行路径 |
| 低门槛 | scripts/、experience/INDEX.md | 变更通知即可 | 影响面可控 |

**经验文件质量原则**：写"陷阱条件"不写"个人偏好"；条目标注日期，超 6 个月标记待审查；少而精——5 条验证过的陷阱胜过 50 条未经检验的注意事项；实验性经验先进 memory/ 个人验证，确认普适再提炼入 experience/。
