# 讲师手册 - 第二部分：架构深挖 —— 工程化 Agent 系统设计

## 课程目标
深入拆解 Agent 的内部运作机制，使学员具备设计和定制企业级 AI 研发 Agent 的架构能力。

---

## 2.1 Agent 核心架构：S-P-A（感知-规划-执行）

### **要点 1：Runner（执行器/生命周期管理）**
- **核心结论**：Runner 是 Agent 的心脏，负责维持任务循环（Task Loop）和状态流转。
- **讲解内容**：
    - Runner 的职责：初始化环境、接收目标、调度 Planner 进行规划、调用执行工具、并基于观察结果进行下一步循环。
    - 关键特性：状态机持久化（防止崩溃后丢失进度）、超时中断（避免模型无限死循环）。
- **举例细节**：
    - **逻辑演示**：一个 Agent 在修复 Bug 时，Runner 需要记录当前的修复尝试次数，如果连续 5 次失败，应触发降级逻辑或请求人工干预。

### **要点 2：Planning（任务规划层）策略**
- **核心结论**：高效的规划机制决定了 Agent 处理复杂问题的深度。
- **讲解内容**：
    - **静态拆解**：对于已知结构的常规任务（如：根据 Spec 生成脚手架代码），预设好的步骤优于动态生成。
    - **动态决策（ReAct 模式）**：对于未知路径的任务（如：定位一个诡异的线上 Bug），Agent 需要实时“思考-行动-观察”。
    - **Self-Reflection**：引入独立的 Reviewer Agent 对规划出的步骤进行可行性评估，减少无效尝试。
- **举例细节**：
    - **对比实验**：直接让 AI 改 Bug（易产生不完整修复）vs. 让 AI 先列出排查路径、列出涉及文件、再分步执行修改。

### **要点 3：Memory（记忆层）多级架构**
- **核心结论**：记忆管理是解决 Token 限制和保持上下文一致性的核心。
- **讲解内容**：
    - **Working Memory**：当前会话最相关的上下文，需要动态摘要以释放空间。
    - **Project Context**：通过 AST（抽象语法树）或 Code Graph 建立的代码索引，让 Agent 能够“秒搜”依赖。
    - **Long-term Memory**：存储团队的编码规范、历史的最佳实践（Best Practices），常以向量数据库（RAG）形式存在。
- **举例细节**：
    - **演示场景**：当 Agent 处理一个跨文件调用时，它是通过 Project Context 自动发现相关联的 API 定义，而不是盲目搜索。

## 2.2 技能与工具系统（The Body）

### **要点 1：技能（Skill）即代码**
- **核心结论**：将复杂的业务逻辑封装为标准化的 CLI 工具或函数，是确保 Agent 执行确定性的最佳手段。
- **讲解内容**：
    - 为什么不直接让 Agent 写原生代码？因为封装后的 Skill 提供了一层语义抽象和更强的容错处理。
    - 技能库应包含：本地编译工具、代码重构原子操作、测试运行器等。
- **举例细节**：
    - **技能演示**：为一个遗留系统的数据库操作封装一个 `db-query-skill`，该技能自带 SQL 注入检查和超时处理。

### **要点 2：Tool-use 设计模式**
- **核心结论**：模型调用工具的协议必须足够清晰（通常基于 JSON Schema）。
- **讲解内容**：
    - 参数最小化原则：为 Agent 设计工具时，参数越少，模型出错率越低。
    - 工具反馈机制：执行结果应包含完整的 stdout/stderr，让 Agent 能够根据错误信息自我修复。
- **举例细节**：
    - **工具配置**：在 `tool_definition.json` 中明确描述 `grep_search` 工具的功能、限制和必填参数。

### **要点 3：沙箱环境设计**
- **核心结论**：执行 Agent 生成的代码必须在受控、隔离的环境中进行。
- **讲解内容**：
    - 探讨基于 Docker 或 MicroVM（如 Firecracker）的隔离方案。
    - 资源限制：CPU、内存和网络访问的严格管控，防止 Agent 意外执行恶意代码或耗尽主机资源。
- **举例细节**：
    - **架构图示**：展示 Agent 在独立的 Container 中进行 `npm install` 和测试运行，而主机环境保持绝对安全。
