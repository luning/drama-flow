# AI 原生研发案例分享

AI 工具已经普及，但提效结果参差不齐——根本原因目前不在模型，在于研发过程中所依赖的产物和知识并不利于 Agent 消费，导致生成效果不理想。本次分享围绕"AI 原生"这条主线，从需求、设计、开发到测试，通过一个案例逐环节演示如何改造产物和知识组织，最终建立可持续进化的知识工程。

---

## 围绕 Agent 重新设计研发要素的思路（5min）

- 工具用上了，但提效结果参差不齐——提效天花板不是模型，而是 Harness
- 现有工作流及产物并不是为 Agent 设计的，各环节改进的方向

## 把需求结构化组织起来，提升Spec生成效果（15min）

- PRD 天然描述增量，Agent 消费时略显不足
- 将业务规则组织成结构化的md文档，优化 PRD 编写流程
- 从 PRD 和业务规则生成 Spec，作为多方合同
- 实施中的问题及建议

## 建立可执行的设计系统，避免人工翻译（10min）

- 现有 UI/UX 的流程及产物并不利于 Agent 消费
- 建立可执行设计系统，将Figma中的设计规范转移到代码中，前端直接引用
- 设计系统成为开发、Agent、验收的共同消费来源，减少人工翻译和视觉漂移

## 定制 SDD 和知识工程应对复杂系统开发（25min）

- 通过5类知识结构化沉淀研发经验
- 定制 SDD ，继承工具能力的同时适配项目
- 通过路由指令链接任务和知识，让知识按需加载
- 工程师监督下的自动化知识工程进化路径

## Spec 驱动 + Agent 自主执行的自动化体系（5min）

- AC 先行的 Spec 驱动测试：未覆盖 AC 自动补测试、再次验证（自愈循环）
- Agent 探索性验收测试
- 可观测性 + 可测试性是发挥 Agent 最大作用的前提
