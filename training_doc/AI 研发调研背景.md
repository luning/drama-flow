# AI 研发调研背景

## 客户概况

客户为**正浩创新（EcoFlow）**，主要生产移动储能和清洁能源产品，是便携式户外电源领域的全球知名品牌。研发团队涵盖嵌入式固件、跨端 App、后端服务等多个方向。

---

## 当前 AI 应用现状与痛点

### 1. 采用率问题

- 固件团队（C++）AI 应用极少，整体采用率偏低
- 推广初期出现高峰，随后进入"绝望之谷"——工程师不愿沉淀、不愿共享，偷懒惰性明显
- 开发的 Skill 不上传共享，仅自用；不愿写 SDD，经验无法复用

### 2. 资源利用问题

- 公司限制 Token 额度，每人每月 1~2 千（已属较高水平），但普遍只使用最小模型
- 利用率不足，缺乏统一步调；需求吞吐量是否提升尚无答案
- ROI 不明，代码生成占比未见提升，存在"自嗨"风险

### 3. 基建与知识沉淀问题

- 产品缺少 AI Sense，不愿维护 Harness
- 基建团队人力紧张，项目节奏以 IPD/PDU 为主，交付和救火占据大量时间，无暇投入 AI 建设
- 工程师不愿维护文档，架构老旧，只能由效能同学代为建立知识库
- 系统解耦封装不足，模块间依赖重，可能制约 AI 应用效果

---

## 研发流程（以嵌入式需求为例）

```
需求提出 → 工作分解 → 设计先行评审
    ↓
多线并行开发：
  RN端 / H5端 / IoT前端 / 后台 / AI算法 / EMS / 大数据
    ↓
联调（模块整合）→ Showcase & 提测 → 测试验收
    ↓
产品体验确认 → UAT 验收 → Story 结束
```

---

## 调研范围

### 岗位

| 方向 | 说明 |
|------|------|
| 嵌入式开发 | 以 C 语言为主的 EMS、IoT 能源领域开发，AI 编程使用率不高 |
| 互联网 App 开发 | 跨端 App（React Native）+ Java 后端，AI 应用相对较好 |
| 产品 / UX / 测试 | 配合角色，AI 应用普遍较弱 |

### 项目

- **项目 A**：纯软件项目（无嵌入式）
- **项目 B**：嵌入式开发项目

---

## 调研思路

1. 了解各岗位 AI 应用的整体现状和大家反馈的问题
2. 了解各角色的工作习惯，AI使用的实际做法，效果能提升到什么程度，有哪些瓶颈
3. 了解项目文档、代码、交付物的内容及组织管理方法
4. 了解架构，编译部署，测试方面的约束
5. 输出对现状的认识，问题及对策，预期的效果，实施方案

---

## 调研形式

以顾问身份深入上下游各岗位日常工作，计划开展 **3~4 天**现场调研，方法包括访谈、观察与工作跟随。
