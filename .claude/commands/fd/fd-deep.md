<objective>
借鉴"测试时计算"（Test-time compute）理念，对棘手的设计问题同时启动 4 个并行子 Agent，
从不同视角独立推演，由主 Agent 汇总校验，输出综合最优方案写回 FD 的 Solution 节。

适用场景：
- 技术方案不确定，需要多路推演后取最优解
- 涉及复杂依赖链，单一视角容易遗漏
- 架构决策前的"压力测试"
</objective>

<context>
目标 FD：$ARGUMENTS

@CLAUDE.md
</context>

<process>

## Step 1 — 读取 FD

找到并读取 `fd/` 下对应的 FD 文档，提取：
- Problem（问题描述）
- 当前 Solution（若有草案）
- Files to Modify（影响范围）

## Step 2 — 并行启动 4 个子 Agent

使用 Task 工具同时启动以下 4 个子 Agent（并行，不要顺序等待）：

**Agent 1 — 算法视角**
```
任务：分析 [FD问题] 的最优算法与数据结构选择。
聚焦：时间复杂度、空间复杂度、边界条件。
输出：推荐方案 + 理由 + 潜在陷阱（不超过 300 字）
项目约束：[粘贴 CLAUDE.md 中的技术栈部分]
```

**Agent 2 — 架构视角**
```
任务：分析 [FD问题] 对系统架构的影响。
聚焦：模块边界、层次违规风险、接口契约变更。
输出：推荐方案 + 理由 + 潜在陷阱（不超过 300 字）
项目约束：[粘贴 CLAUDE.md 中的架构约束部分]
```

**Agent 3 — 风险视角**
```
任务：对 [FD问题] 进行风险扫描。
聚焦：并发安全、数据一致性、回滚路径、已有测试破坏风险。
输出：风险清单（高/中/低）+ 缓解建议（不超过 300 字）
受影响文件：[Files to Modify 列表]
```

**Agent 4 — 增量视角**
```
任务：为 [FD问题] 设计最小可验证的增量实现路径。
聚焦：如何将大改动拆成可独立提交的小步骤，每步可验证。
输出：有序步骤列表 + 每步验收标准（不超过 300 字）
项目约束：[粘贴 CLAUDE.md 相关部分]
```

## Step 3 — 汇总与校验

等待 4 个 Agent 完成，汇总输出：

1. **共识点**：4 个视角都认可的结论
2. **分歧点**：视角间存在冲突的地方，分析原因
3. **综合方案**：基于 4 个视角推导出的最优路径

## Step 4 — 更新 FD Solution

将综合方案写入 FD 文档的 Solution 节。若原有 Solution 有 `%%` 疑问批注，逐条解答并删除 `%%`。

在 FD 末尾追加：
```markdown
## Deep Analysis Log

**日期**：YYYY-MM-DD  
**触发原因**：[为什么启动了 /fd-deep]  
**关键决策**：[一句话描述最终选择]
```

## Step 5 — 输出摘要

展示 4 个视角的核心结论对比表，以及最终选择了哪条路径和理由。

</process>
