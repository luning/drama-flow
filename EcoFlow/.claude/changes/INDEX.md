# 变更类知识 — 中央索引

索引**变更类知识**（设计决策 + 任务经验）——这两类信息从当前代码或规格本身看不出任何线索，探索再深也不会主动碰到，必须在规划变更前主动加载。**结构知识、领域知识等现状类知识不在此索引**，靠各自目录下的说明文档和正常探索即可发现，不需要被动等待推送。

按任务类型/模块查表加载对应的经验或决策文件：

| 任务类型 | 任务经验（EXPERIENCE.md） | 核心陷阱 | 设计决策 |
|---------|--------------------------|---------|---------|
| BMS 保护逻辑 / ADC 采样 / SoC 估算 / 均衡 | `EcoFlow/src/bms/EXPERIENCE.md` | FINIT 序列、I2C 竞态、库仑计清零 | — |
| EMS 调度规则 / 模式切换 / TOU 策略 | `EcoFlow/src/ems/EXPERIENCE.md`（待补充） | 并网切换握手、夏令时 TOU 双执行 | — |
| IoT MQTT / OTA / Shadow / 遥测 | `EcoFlow/src/iot/EXPERIENCE.md` | 上线风暴、OTA 分区兼容、消息幂等 | — |

"设计决策"列目前为空——本项目尚未积累需要记录的架构级决策（否决方案、设计惯例）。一旦出现（例如"为什么 IoT 只能通过 `ems_mode_switch()` 转发指令，而不是直接扩展 `ems_setpoint_queue`"这类否决过的替代方案），在此表新增一行，文件建议存于 `EcoFlow/knowledge/decisions/`。

## 谁负责把这份索引主动送到 Agent 面前

这份索引本身不会自动生效——需要一个主动注入机制在 SDD 工具**开始规划变更**的那一刻把它摆到 Agent 面前，而不是指望 Agent 自己想起来查：

- 使用 OpenSpec：对应 Schema 的 `proposal`/`design` artifact 的 `instruction` 字段里写明"起草前先查本索引"
- 使用 Superpowers：见 `EcoFlow/CLAUDE.md` 的"SDD 最小约束"一节

## 使用方式

条目本身就是最终结论（陷阱的触发条件/症状/修复、决策的否决理由），不需要另外转述。Agent 在任务开始前按模块加载对应文件；任务完成后若发现新陷阱或做出新的架构决策，追加到对应文件末尾，并在本索引补充一行。
