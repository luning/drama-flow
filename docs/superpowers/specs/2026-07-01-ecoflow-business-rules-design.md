## 一、目标与受众

### 目标

在项目仓库中创建三份逼真、详尽的 EcoFlow（正浩创新）EMS 和 IoT 系统业务规则文档，遵循 [结构化业务规则.md](../../training_doc/知识点/结构化业务规则.md) 的方法论，**重点体现硬件相关的业务规则**（时序/信号/寄存器层面的约束）。

每份文档同时服务于两类受众：
- **AI Agent**：作为系统开发的 SSoT（唯一事实来源），Agent 读取后可直接生成 SPEC 和测试用例
- **PM / 开发团队**：作为 IoT 硬件场景结构化业务规则的参考模板，展示双层结构的最佳实践

### 非目标

- 不生成实际可执行的代码（SPEC 或测试用例由后续流程单独生成）
- 不覆盖 EcoFlow 所有产品线，只聚焦三个核心子系统
- 不做通用模板框架开发——这三份文档本身就是模板

## 三、文档模板（双层结构）

每份文档采用统一的"业务规则正文 + 硬件细节附录"双层结构：

```
┌─────────────────────────────────────────┐
│  YAML 文件头（id/title/owner/related）   │
├─────────────────────────────────────────┤
│  业务规则正文（~2/3 篇幅）                 │
│  ├── 业务流程（端到端场景链）              │
│  ├── 运行态状态机（设备状态跃迁）          │
│  ├── 异常处理表（故障模式 + 恢复策略）      │
│  └── 验收标准（AC，可被测试框架消费）       │
├─────────────────────────────────────────┤
│  硬件细节附录（~1/3 篇幅）                 │
│  ├── 寄存器映射表（地址 / 位域 / R/W / 默认值）│
│  ├── 通信帧格式（报文结构 / 字段定义）       │
│  ├── 时序约束清单（采样周期 / 超时 / 抖动）   │
│  └── 保护阈值表（电压 / 电流 / 温度 + 回差）  │
└─────────────────────────────────────────┘
```

**双层引用机制：**
- 正文 → 附录：`[详见 §寄存器-0x2A]`，Agent 可沿锚点跳转
- 附录 → 正文：寄存器行尾标注 `→ AC-3`，反向追溯业务意图
- YAML `related` 字段链接跨文档依赖

**行内约束标记（全文使用）：**

| 标记 | 含义 | 强制程度 |
|------|------|---------|
| `[MUST]` | 硬性要求，对应 AC 覆盖 | 不可降级 |
| `[MUST NOT]` | 安全/硬件红线 | 不可降级 |
| `[SHOULD]` | 建议实现 | 不做需说明原因 |
| `[CONSTRAINT:timing]` | 时序约束 | 硬件级别 |
| `[CONSTRAINT:safety]` | 安全约束 | 硬件级别 |

### 业务流程（示例：RULE-BMS-001 电芯采样流程）

```
MCU 启动 → I2C 初始化（400kHz Fast Mode [CONSTRAINT:timing]）
  → 配置 ADS1115 多路复用器通道 0-15 [详见 §寄存器-0x01]
  → 每 100ms [CONSTRAINT:timing] 执行全电芯扫描：
      1. 依次切换 MUX 通道（通道切换后 delay ≥ 8μs）
      2. 触发单次 ADC 转换（转换时间 ≤ 1.1ms @ 860SPS）
      3. 读取 16-bit 转换结果 → 换算为实际电压
      4. 检查是否触发保护阈值 [详见 §保护阈值-电压]
  → NTC 温度采样（独立 ADC 通道16-19，每 500ms 采样一次）
  → 数据写入环形缓冲区（深度 16 组，供 SoC 和均衡算法消费）
```

### 异常处理表示例

| 场景 | 检测方式 | 硬件动作 | 恢复条件 | 告警级别 | 对应 AC |
|------|---------|---------|---------|---------|---------|
| 任一电芯电压 > 3.65V | ADC 比较器 | MOSFET CHARGE_DSG 关断（≤50μs）[详见 §时序-OVP] | 所有电芯 < 3.40V + 滞回 | 1-严重 | AC-3 |
| 短路电流 > 200A | 硬件比较器（BQ76952 SCD 引脚锁存） | CHG/DSG FET 同时关断（≤ 10μs [CONSTRAINT:safety]） | 移除负载 + 上位机发送清除命令 [详见 §寄存器-0x1F] | 0-紧急 | AC-7 |
| 电芯温差 > 15°C | 软件比较 NTC 最大值与最小值 | 限制充放电功率至 50% | 温差 < 10°C 持续 60s | 2-一般 | AC-5 |

### 验收标准示例

```
AC-1: ADC 扫描完成中断触发 → 16 路电压值在 110ms 内 [CONSTRAINT:timing] 全部更新到环形缓冲区
AC-2: 任一电芯电压 > 3.65V → MOSFET CHARGE_DSG 在 50μs 内关断，状态寄存器 0x10 bit2 置 1
AC-3: OVP 触发后若所有电芯 < 3.40V → 上位机发送清除命令（0x1F ← 0x02）后方可恢复导通
AC-4: 短路锁存（SCD）触发后 [MUST NOT] 自动恢复，[MUST] 等待上位机清除命令
```

### 硬件细节附录量级

| 附录 | 数量 |
|------|------|

## 七、质量要求

1. **逼真性**：寄存器地址、位域宽度、阈值数值必须合理且自洽（例如 16S LFP 储能系统的电压阈值取值需符合锂电池化学特性）
2. **一致性**：同一份文档内和跨文档间的数值、命名、单位保持一致（例如 bms-inverter 中的电芯数量 16S 需与 home-energy 中的系统电压 51.2V 匹配）
3. **可追溯性**：每条 AC 至少关联一个硬件约束，每条硬件约束至少对应一条 AC
4. **OKF 兼容**：YAML 文件头字段完备，正文 Markdown 结构清晰，`cat` 即读

---

## 八、非功能约束

- 每份文档正文（不含附录）控制在 500-800 行 Markdown
- 附录中表格使用 GitHub Flavored Markdown 表格语法
- 状态机使用 Mermaid 或 ASCII art 绘制
- 时序约束统一使用 `[CONSTRAINT:timing]` 标记
