## 各章内容要点

### 第 1 章：PRD 天然描述增量

**论证主干**（单条，不分支）：

1. PRD 天然是增量文档——v1.0 写登录，v1.2 加"记住我"，v2.0 改 Token 策略。这不是缺陷，而是 PM 与下游协作的最佳模式：下游消费增量信息最有效。
2. 这带来一个后果：当前全貌散落在多份历史 PRD 里，没有一份文档告诉你某功能此刻支持哪些场景和约束。
3. 例子：Agent 拿到 v2.0 知道"密码最少 8 位"，不知道 v1.0 定的"邮箱不存在时的错误文案"。
4. 结论：需要一份常青的当前有效文档，作为每个业务概念的唯一事实来源（SSoT）。

**变化**：
- 标题从"Agent 读 PRD 的三个盲区"→"PRD 天然描述增量"
- 去掉"边界模糊""AC 无法自动验证"独立段落（这些是结构化后的衍生收益，不挤在论证主干里）
- 增量示例保留，但视角从"Agent 的困境"转为"增量模式固有特征"

### 第 2 章：不是所有需求都需要结构化

**纯边界划定**：

1. 开头论断：不是所有产品知识都需要结构化。真正需要的是"业务规则"——逻辑密度高、边界清晰、错过就是线上事故。
2. 四种性质分类表：

| PRD 常见内容 | 特征 | 需要结构化？ |
|------|------|-------------|
| 业务规则 | 逻辑密集，可穷举，漏掉就是 bug | 是 |
| 探索方向 | 方向未定，随时可能推翻 | 否 |
| 流程路径 | PRD 正文已有完整表达 | 否 |
| 界面调整 | 设计稿/代码已有全貌 | 否 |

3. 判断标准：无法通过使用产品直观穷举 + 恰好是测试的重心 → 该结构化。

**变化**：
- 去"四象限"措辞（不是 2x2 矩阵）
- 移除"为什么 PM 需要专门维护全貌"→ 并入第 3 章
- 移除"测试视角"→ 并入第 3 章

### 第 3 章：PRD 与业务规则的协同

**A 板块 — 全景：业务规则在体系中的位置**
- 流转图：PRD（变更叙事）→ 业务规则（当前全貌）→ SPEC（技术边界）→ 测试用例（验证）
- 三者对比表（主导方、描述对象、包含内容）
- 为什么不是三合一：维护责任不同，ID 引用已建立可追溯关联
- 三方 ID 引用联动示例

**B 板块 — 协作：PRD 与业务规则的双轨运行**
- PM 不是没有全貌认知，而是没有把它规范化地沉淀下来——结构化就是把已存在的全貌认知用 Agent 能消费的格式落地
- 双轨模型：PM 写 PRD → Agent 提取变更 → 更新业务规则 → git diff → PRD 引用链接
- PM 维护方式：直接编辑 Markdown 或 Agent 辅助（自然语言→Agent 格式化+提交）
- PRD 引用规则的方式：全貌链接 + 变更 diff
- 测试视角收束：AC 可被测试框架直接消费，这是 PM、开发、测试的三方对齐

**来源**：
- 从 v1 第 2 章移入：PM 全貌、测试视角
- 从 v1 第 7 章移入：三者对比表、ID 引用联动、为什么不是三合一、流转路径
- 保留 v1 第 3 章：双轨模型、维护方式、PRD 引用方式

### 第 4 章：业务规则结构化实操指南

**以 OKF 开头作为方法论引子**：

> OKF（Open Knowledge Format）是 Google Cloud 2026 年发布的开放规范——Markdown + YAML 文件头，对人友好、对 Agent 友好。三个结构原则恰好对应本文做法：一个概念一份文档、结构化 YAML 文件头、Git 仓库管理。

然后展开具体做法：

1. 核心原则：一个概念一份文件 = SSoT，Git 记录演进
2. 目录结构：`business-rules/auth/login.md`，路径即概念 ID
3. 粒度选择：单一变更原因 + 5-15 条核心 AC，附粒度对比表
4. YAML 文件头：id / status / owner / updated / related
5. 正文结构：业务流程 + 异常处理表格 + 验收标准
6. 行内约束标记：`[MUST]` / `[MUST NOT]` / `[SHOULD]` / `[CONSTRAINT:类型]`
7. Git 管理：`git log` 看演进，CI 检测关联 SPEC 更新

### 第 5 章：推行策略与常见难点

三个难点 + 渐进分级，内容基本不变：

| 难点 | 对策 |
|------|------|
| PM 接受度 | Agent 辅助 / Wiki 形式展示 |
| 存量文档多 | 新旧双轨，触碰则改，核心流程先行 |
| 改造幅度 | 最小可行 → 中等 → 完整，三级渐进 |
